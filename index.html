🎯 Core UCLDP framework

How the user-centric privacy pipeline works

Local Differential Privacy adds noise to your data before it leaves your device. The trade-off: too little noise leaks personal information, too much makes the data useless. UCLDP improves on standard LDP in two ways — it lets you choose the privacy budget ε based on your priorities (ULDP), and it spreads the noise budget unequally across features so the important ones stay accurate (MIC-DP).

Step 3 — MIC-DP adds smart noise CORE CONTRIBUTION

Standard LDP adds the same noise to every feature. But not every feature matters equally for the analyst's forecast. MIC-DP measures each feature's Maximum Information Coefficient against the prediction target and gives more budget (less noise) to the features that matter most. Same total ε, same formal privacy. Just redistributed.

Each appliance feature has a different MIC score (correlation with grid demand)

Standard LDP — equal noise σ for all

Every feature gets σ = sensitivity / (ε/d). Low-MIC features (fridge, lighting) get the same noise as high-MIC features (heating, EV) — wasting budget on signals that barely matter for the forecast.

MIC-DP — budget ∝ MICα

Feature j gets budget share MICjα / Σ MICkα (with α = 1.5 here). High-MIC features get less noise; low-MIC features absorb more. Total budget identical, formal (ε, δ)-DP unchanged — only the distribution changes.

Why is MIC-DP's advantage bigger at small ε? When the total budget is tiny, every bit matters. Concentrating it on the features that drive the forecast (high MIC) preserves signal where it counts. At loose ε (5.0, 10.0), even uniform noise is small enough that the gap narrows — and the dissertation reports this exact pattern in Figure 9.1.
Quick note — federated setting (LDP-MIC)

When many homes share data for a neighbourhood-wide forecast, no central server can be trusted with raw inputs. LDP-MIC is the federated variant: each home runs MIC-DP locally before any data leaves the device. The server sees only noisy outputs and uses trust-weighted aggregation to discard suspicious updates. Same core algorithm, distributed.

💬 Optional system extension

PrivAgent — a conversational way to set your priorities

Some users don't enjoy moving three sliders. PrivAgent replaces the slider interface with six short "would you rather" questions in plain language. It then converts your answers into the same Privacy / Usefulness / Compute weight vector that Step 2 needed. PrivAgent is a standalone extension — the core UCLDP results in Tab 1 don't depend on it. Whether your weights come from sliders, PrivAgent, or a default, the rest of the pipeline works the same.

In this tab you'll see the dialogue, the weights it produces, and a comparison with what you set with sliders on Tab 1. We're not feeding these weights back into Tab 1 — the comparison is just to validate whether the dialogue captures what the sliders do.
